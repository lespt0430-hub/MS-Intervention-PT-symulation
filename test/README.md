# 결과 수집 점검

```bash
node test/collect.test.js
```

Node 18 이상이면 됩니다. 설치할 것은 없습니다.

## 무엇을 보는가

구글 Apps Script 웹 앱은 보통 서버와 동작이 달라서, 로컬에 아무 서버나
세워 놓고 시험하면 실제 배포에서만 터지는 문제를 놓칩니다.
`mock-apps-script.js` 는 그 차이를 그대로 흉내 냅니다.

- `POST .../exec` 는 결과를 바로 주지 않고 **302 로 다른 출처**
  (`script.googleusercontent.com`)로 넘긴다 → CORS 검사가 두 번 일어난다
- **OPTIONS(사전요청)를 처리하지 못한다** → 사전요청이 한 번이라도 나가면
  실제로는 전송이 통째로 막힌다. 점검에서 이걸 세고 있다
- `doPost` 가 **동시에 여러 개** 돈다 → 잠그지 않으면 결과가 사라진다

점검 항목은 7가지입니다.

| # | 내용 |
|---|---|
| 1 | 정상 제출 — 302 경유, 사전요청 0회, 점수·검사·치료 값이 제대로 실리는지 |
| 2 | 인터넷이 끊겼다가 복구 — 보관함에 쌓였다가 자동 재전송되는지 |
| 3 | 서버 무응답 — 밀린 게 많아도 첫 건에서 멈추고, 남은 기록은 보존되는지 |
| 4 | 동시 제출 12건 — 잠금 없이는 유실되고, `LockService` 로는 전부 남는지 |
| 5 | 교수 조회 — 아이디·비밀번호가 틀리면 거부되는지 |
| 6 | 엑셀(.xlsx) — 진짜 ZIP/XML 구조로 만들어지는지 |
| 7 | 수집이 꺼진 상태에서 이 PC 기록만 엑셀로 받기 |

만들어진 엑셀은 `test/out/` 에 남습니다. 엑셀로 직접 열어 봐도 됩니다.

## 4번이 실패하면

`PROFESSOR_SETUP.md` 의 스크립트에서 `LockService` 부분이 빠졌다는 뜻입니다.
스크립트를 고쳤다면 **배포 → 배포 관리 → 편집 → 버전 '새 버전' → 배포**까지
해야 실제로 반영됩니다.
